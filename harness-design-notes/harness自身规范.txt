1. 科研流程正确性：像顶级科研学者一样完成研究

以《科研问题发现与创新方法设计方法论》作为科研层 Ground Truth。完整主线是：

领域认知 → 好问题 → 根因 → 方法需求 → 方法设计/迁移/最小组合 → 因果验证。

E2E 中每一步都不能只检查“有没有生成文件”，而要检查其科研判断是否达到明确标准：

领域认知：是否真正建立“问题—方法—机制—有效条件—失效条件”地图，而非论文罗列。
问题发现：问题是否同时满足 真实存在 + 尚未被很好解决 + 足够重要，尤其不能把“Agent 没搜到”当成“领域没解决”。
根因分析：是否通过 1a–2b 从失败现象进入机制层，并得到可干预的因果链，而不是停留在抽象解释。
方法设计：是否严格由“研究问题 → 根因 → 要改变的机制 → 所需能力”自然推出，而非先有算法再找理由。
方法迁移/组合：优先寻找解决主要根因的核心机制；只有核心方法存在明确缺口时才增加模块，每个模块必须对应具体瓶颈。
验证：不能只看最终性能，必须完成 3a–4b，证明“根因 → 方法干预 → 中间机制改变 → 原始问题改善”的因果链。

所以科研层真正要测试的是：

如果把 Harness 去掉，只看它做出的科研判断，一个顶级研究者是否会认可这一步的证据、推理和下一步决策。

2. Harness 正确性：保证 Agent 真的按照上述科研流程执行

第二层不是再次判断科研内容，而是检查 Harness 是否可靠地约束 Agent 执行科研流程。

每个关键阶段至少应明确：

输入契约 → 执行任务 → 输出 Artifact/State → 可判定标准 → 不满足时的回退路径 → 下一阶段准入条件。

然后根据真实失效风险决定是否需要：

Gate：下一阶段必须建立在已确认的关键结论上时。
Validator：某项要求能够明确机器判定时。
Hook：Agent 可能绕过流程、遗漏强制动作，且需要执行时强制约束时。
State / Artifact：后续阶段必须可靠引用、追溯或绑定上游结论时。
Independent reviewer / subagent：只有“执行者自我判断”确实不足以保证可靠性时。

核心原则不是“机制越多越可靠”，而是：

只有存在真实的 Agent 自由度或失效模式，才增加约束；使用能够消除该失效模式的最小机制。

否则就是防御性 Harness。
