National Academies 对科学过程的概括就是“iterative, dynamic”，研究者会在提出解释、寻找证据、修改问题和重新测试之间反复移动

当前harness应该按照真正的顶级科研学者去做科研，我举个例子，
大量阅读 impedance control
→ 发现很多工作采用弹簧阻尼类环境模型（可以是自己横向对比总结，可以是从某一篇文献中找到灵感）
→ 怀疑这一假设与真实软环境不符
→ 转向 contact model 重新深挖
→ 再形成具体问题
→ 根据问题设计方法。

领域认知->找到真正值得做的问题->重调研（深挖）->设计创新方法。

--------------------------------------------------

找到真正值得做的好问题，因为很多时候文献都是避重就轻的，往往会弱化他的失败（不是全部），这种研究问题的线索lead/灵感往往来自于两种情况：1）对该领域论文进行横向总结对比，找到大家共性的失败，比如发现大家都使用某种假设，然后去思考这种假设在什么有现实意义的情况下会失败；2）由某篇或者某几篇文献启发，比如他们可以在discussion/conclusion提到某些限制，或者文章本身就提出了一个很有意思的idea但是做的不够完善，然后，再对比该领域的其他论文，检查该lead是否能转化为真正值得研究的问题

-------------------------------------------------

**领域认知 → 发现高潜问题线索 → 围绕线索定向深挖 → 确认真正值得研究的问题 → 根因分析 → 创新方法设计**

核心原则是：**一个问题是否真正值得研究，通常需要经过针对该问题的第二轮调研才能确认。**

## 1. 第一轮：建立领域认知

这一阶段的目标不是寻找某个具体 gap，而是建立足够可靠的领域认知地图：

**领域目标 → 核心任务 → 主要问题 → 方法家族 → 为什么有效 → 依赖什么假设 → 在哪里失效 → 当前矛盾**

重点是建立：

**问题—方法—假设—有效条件—失效条件**

之间的关系。

领域认知应覆盖足以支撑后续科研判断的关键脉络，包括：

- 核心研究目标与任务；
- 主要问题及其演化；
- 主流方法及其作用机制；
- 方法成立所依赖的条件和假设；
- 已知失败场景与能力边界；
- 当前开放问题、争议和瓶颈。

不要求穷尽整个领域，而要求达到能够识别潜在重要问题的认知深度。

**目的不是直接产出 idea，而是建立发现和判断好问题所需的领域认知。**

---

## 2. 从领域认知中发现高潜问题线索

在建立领域认知过程中，应主动寻找值得进一步追踪的异常、矛盾和边界，例如：

- 大量工作共享某个可能不成立的关键假设；
- 某类方法在特定场景下系统性失效；
- 两个重要目标长期无法同时满足；
- 新工作暴露出过去方法未覆盖的能力边界；
- 某个真实且重要的场景长期与现有理论或方法不匹配；
- 某类失败反复出现，但尚缺乏令人信服的机制解释。

此时得到的是：

**problem lead**

而不是已经成立的研究问题。

Problem Lead 只是需要进一步验证的研究线索；只有经过针对性深挖、证据验证、收缩或重构后，才可能形成 Problem Candidate。
例如：

> 大量 impedance-control 工作采用简单弹簧阻尼环境模型，而真实软接触具有明显更复杂的非线性、时变或历史依赖特性。

这可以构成一个高潜问题线索，但尚不足以直接进入方法设计。

---

## 3. 第二轮：围绕 problem lead 定向深挖

发现高潜线索后，应从广泛领域调研切换到围绕该线索的 targeted deep dive。

核心问题包括：

> 这个现象到底有多普遍？  
> 已有研究已经解决到了什么程度？  
> 在什么条件下它真正造成能力失败？  
> 最接近的已有方法是什么？  
> closest prior 为什么仍然没有解决？  
> 是否存在反证，说明这个问题其实已经被解决、并不重要，或者原始判断有误？

这一阶段本质上是对问题进行**验证、收缩和重构**：

**粗线索  
→ 查证真实性  
→ 确定发生条件  
→ 找 closest prior  
→ 判断已有解决程度  
→ 主动寻找反证  
→ 缩小问题边界  
→ strengthen / narrow / reframe / reject  
→ 形成精确研究问题**

问题发现因此不是一次性过程，而是：

**提出判断 → 检索证据 → 更新判断 → 再检索 → 再收缩**

如果证据不支持，应允许直接削弱、重构或放弃该 problem lead，而不是强行将其发展成研究问题。

---

## 4. 确认真正值得研究的问题

经过针对性深挖后，一个问题至少应同时满足：

**真实**  
问题确实存在，并有可靠证据支持，而不是研究者主观想象。

**未解决**  
strongest / closest prior 仍存在明确且实质性的能力边界，不能仅依靠已有方法的直接应用、简单调参或常规扩展解决。

同时应主动寻找 strongest counterevidence，并检查是否存在能够解释该现象的 alternative explanation，避免把已经解决、并不重要或解释错误的问题误判为研究问题。

**重要**  
解决该问题能够实质改变系统能力、适用范围、可靠性或科学认识。

**精确**  
能够明确指出：在什么条件下、什么系统中、由于什么限制、出现什么失败。

**可证伪**  
能够设计实验或分析证明该问题是否真实，以及提出的解释是否成立。

**可回答**  
问题在现实研究条件下具有可分析、可实验或可验证的研究路径，而不是无法落地检验的宽泛命题。

只有满足这些条件，才应：

**commit to the problem**

即将经过深挖和验证的 Problem Candidate 升格为真正值得研究的问题。

---

## 5. 根因分析

确认问题值得研究后，仍不能直接进入方法设计。

首先必须回答：

> **为什么现有方法解决不了这个问题？**

需要从失败现象逐步追溯到可干预的主要因果机制：

**失败现象  
→ 失败发生条件  
→ 中间异常  
→ 现有机制为何失效  
→ 更深层原因  
→ 可被技术干预的主要根因**

可采用：

**1a 观察失败现象  
→ 1b 归类并提出根因假设  
→ 2a 递归追问为什么  
→ 2b 建立完整因果链**

目标不是给问题附加一个解释，而是确定：

> **究竟是哪一个主要机制阻止现有方法解决问题。**

必要时应再次进行机制层面的 targeted research，用文献和实验检验根因假设。

---

## 6. 创新方法设计

只有明确根因之后，才能定义方法。

基本逻辑是：

**根因  
→ intervention target  
→ 方法必须具备的能力  
→ Design Obligations  
→ 搜索能够满足这些能力的方法  
→ minimal dominant solution**

即先问：

> 为了切断这条因果链，方法必须改变哪个中间机制？

再问：

> 哪种技术能够最直接、最充分地实现这种改变？

方法搜索可以依次考虑：

1. 本领域已有方法能否直接解决；
2. 本领域其他问题中的方法能否迁移；
3. 其他领域是否存在满足相同 Design Obligation 的机制；
4. 如何改造这些方法，使其在当前问题条件下成立。

只有存在明确的 **residual MUST gap** 时，才增加额外模块。

因此方法设计必须满足：

**每个核心模块对应一个明确瓶颈。**

不能因为某个模型新颖、流行或可能提高指标就加入方法。

---

## 7. 完整科研主流程

最符合顶级研究实践的主流程应为：

**领域认知  
→ 发现问题线索  
↔ 针对性深挖  
→ 确认真正值得研究的问题  
→ 根因分析  
↔ 必要的机制调研  
→ 创新方法设计  
→ 因果验证 / 实验验证  
→ 必要时根据结果回退并重新修正问题、根因或方法**

其中，文献调研不是一次性的 Stage 1，而是贯穿不同科研阶段，并承担不同任务：

- **第一轮广调研**：建立领域认知；
- **问题阶段深挖**：验证问题的真实性、未解决性和重要性；
- **根因阶段深挖**：判断为什么现有方法失败；
- **方法阶段深挖**：寻找能够干预关键机制的技术方案。

因此，problem discovery 本身必须是：

**思考 → 检索 → 查证 → 反证 → 更新判断 → 收缩或重构问题**

的迭代过程，而不能在 Field Map 完成后一次性生成 Problem Candidate 并直接进入方法设计。

最关键的边界是：

> **先发现一个值得怀疑和追踪的问题线索，再通过针对性深挖确认它是否是真正值得研究的问题；确认问题后继续通过根因分析、方法设计和因果验证形成闭环，并在证据不支持时允许回退修正。**
