从失败中找问题并分析根因 + 通过顶刊顶会的方法迁移去解决问题，关键点有两个，第一个是分析根因到底能不能分析出来，就像是之前的固定阻抗控制的例子，第二个更关键，能否找到其他领域的方法进行方法迁移，最关键的三点就是先找到其他领域的问题-干预对，然后判断是否是机制同构，然后自然的迁移/改造。

ARIS Method Design 科研标准与流程最终版

======================================================================
总纲与内容优先级
========

“五级标准和优先级”用于规定全文的最终目标、科研问题优先级和工程化边界；它是全文的总纲与优先级约束，不作为后续正文的目录结构。

## 一级：唯一最终目标

**优化 Method Design 模块，使harness能设计出真正达到顶会顶刊标准的方法。**
整个任务固定分两阶段：
**Phase I：逆向分析顶会顶刊 → 搞清楚真实科研流程 → 形成明确科研标准。**
**Phase II：把已经确定的科研流程和标准转化为 Method Design Harness。**

---

## 二级：Phase I 必须解决的核心科研问题

### 1. 搞清楚“强方法到底是怎么产生的”

当前重点研究：

> **从失败中找问题并分析根因 + 通过方法迁移解决问题。**

完整主干：
**真实 Failure → 搞清楚 Root Cause → 推出 Required Mechanism Change → 主动寻找解决该机制问题的强 Source Mechanism → 完成方法迁移/改造 → Strong Method Seed。**
其中 **RCA 怎么做、怎样从 RCA 推出 Required Mechanism Change、怎样主动找到 Source Mechanism**，都属于主干本身，不能降成验收细节。

### 2. 搞清楚什么样的方法才达到顶会顶刊级

原始核心假设保留：

> **强源方法 + 真实同构 + 非平凡目标域改造 + 目标域尚未被已有工作覆盖 → 高概率形成强创新 MethodSeed。**

后续案例对其做了精化：

* **真实同构的核心：`Source Intervention = Target Root Cause 真正需要的干预`。**
* **目标域改造由真实 Target Constraints 驱动；真实冲突必须闭合。**
* 最终 Method 必须具有足够强的 **Scientific / Mechanism Delta**，不能只是合理迁移。

### 3. 用真实顶级论文把上述科研过程验证清楚

最终科研标准不能靠理论上“应该如此”确定。
必须：

> **多篇顶级成功案例 + 同路径近失败案例 + 必要的反事实证据 → Cross-Case Causal Induction**

最终真正区分：
**普通方法迁移 / application / method soup**
与
**顶会顶刊级 Strong Method Seed。**

---

## 三级：完成二级目标时必须遵守的核心分析要求

1. **恢复 Method Genesis：**
   `失败 → 根因 → 需要改变什么机制 → 为什么想到这个源机制 → 为什么它能迁 → 为什么必须这样改造 → 最终 Method`。
2. 始终回答三个核心问题：
   **为什么想到这个源机制？为什么逻辑上能迁？为什么迁移后会自然形成一个新的强方法？**
3. **追踪 Method Genealogy。**
   论文经常弱化方法迁移，需要追：
   `Target Paper → 方法前驱 → 核心机制来源论文`。
4. **Root Cause 必须达到机制级。**
   定位真正导致 Failure 的 state / relation / information / representation / constraint / observability / computation / decision structure，并推出 **Required Mechanism Change**。
5. **Source Search 由 Required Mechanism Change 驱动。**
   核心搜索问题是：
   **哪个已有机制已经成功改变了我这里必须改变的 causal/computational variable？**
6. **真实同构检查到 intervention / causal structure 层。**
   原始检查包括：
   `Source Root Cause ↔ Target Root Cause`
   `Source Intervention ↔ Target Required Mechanism Change`
   `Source causal path ↔ Target causal path`
   其中后续证据确认第二项是必要核心，第一项整体一致不再是硬要求。
7. **目标域改造必须自然。**
   分析 Source Mechanism 在 Target 中遇到什么新约束，这些约束怎样迫使机制改变，最终怎样形成新的 Method Structure。
8. **检查目标域是否已经覆盖等价 causal intervention。**
9. **Natural Derivation：**
   删除 Source-domain story 后，Final Method 仍应能从 Target Failure / Root Cause / Required Change 自然推出。
10. **不同论文允许不同 formation logic。**
    不强行给每篇论文制造 Source Method、Root Cause 或迁移故事；寻找大部分/部分论文真实稳定存在的规律。

---

## 四级：把科研逻辑变成可靠流程时需要的具体机制

这一层才包括：

* Simple-Repair Falsifier；
* Design Obligations / Required Capability；
* Candidate Solution Principles；
* Principle Competition（仅在 solution space 欠约束时）；
* Discriminating Prediction / Killer Test；
* Evidence Update；
* Principle Convergence；
* Human Gate；
* Method Adaptation；
* Residual MUST；
* Minimal Necessary Composition；
* Causal Repair DAG；
* No-Orphan-Module；
* Mechanism Delta；
* Scientific Delta；
* Feasibility Closure；
* Counterfactual Necessity Package；
* RCA reopen / Recovery。

这些很重要，但它们是**实现上面科研主干的方法和判据**，优先级低于“到底研究什么科研过程、Strong Method 怎么形成”本身。

## 五级：Phase II 的 Harness 工程化要求

Phase I 冻结后，再把每一步压成：
**Input → Cognitive Operation → Required Evidence → PASS → FAIL → Recovery**
并落实成：
**Agent 可执行 → Reviewer 可判断 → Validator 可检查 → Gate 可阻断 → 失败可回退。**

======================================================================
一、Strong Method 如何从真实 Failure / RCA / 方法迁移中产生
=============================================

当前重点研究：

> **从失败中找问题并分析根因 + 通过方法迁移解决问题。**

真正需要恢复的是：

> **Method Genesis（方法生成过程）。**

对每个方法必须能够重建：

最终 Method
← 目标域必要改造
← 被迁移的核心机制
← Source Method
← Source Problem 及其根因

然后从正方向验证：

目标失败
→ 目标根因
→ 所需机制改变
→ 为什么找到这个源机制
→ 为什么这个源机制真的能解决该根因
→ 为什么必须进行目标域改造
→ 为什么最终形成这个 Method

**只有正反两条链都闭合，才算真正理解了这个案例。**

整个科研过程始终围绕三个核心问题：

1. **为什么会想到这个 Source Mechanism？**
2. **为什么这个 Source Mechanism 真的能够迁移？**
3. **为什么迁移之后会变成一个强的新 Method？**

**其他东西——方法谱系、文献追踪、目标域 novelty 检查、反事实实验、负案例——全部只是为了证明这三个核心问题，不能和它们平级。**

---

1. 从真实 Failure 到 Mechanism-Level Root Cause

---

首先确定真实 Failure：

condition
→ observable failure
→ consequence

Failure 必须：

* 在目标任务和 Operating Envelope 中真实存在；
* 可以被事实、文献、数据、实验或形式分析支持；
* 实际限制性能、能力、理论保证、可识别性或可实现性；
* 不是人为构造的无关极端情况。

随后独立完成 Root Cause Analysis。

不能停在：

* 泛化差；
* 鲁棒性不足；
* 精度低；
* 效率低；
* 数据不足；
* 任务复杂。

必须继续定位真正导致 Failure 的：

* state；
* relation；
* information path；
* representation；
* constraint；
* observability / identifiability；
* computation / optimization structure；
* decision structure；
* causal/computational variable。

目标不是寻找抽象意义上的唯一根因，而是确定：

> **足以解释关键失败，并且能够被方法干预的主要因果机制。**

RCA 必须能够解释 Failure 为什么发生、在什么条件下发生以及哪个关键 causal/computational variable 必须被改变。

---

2. 从 Root Cause 推出 Required Mechanism Change

---

明确 Root Cause 后，依次判断：

1. 根因是什么；
2. 现有方法为什么无法解决它；
3. 要使问题消失，需要改变哪个机制；
4. 新方法需要具备什么能力。

形成：

研究问题
→ 机制级根因
→ 需要改变的机制
→ 方法所需能力

核心原则：

> **研究问题决定需要解决什么；根因决定方法应该做什么；具体算法只是实现手段。**

Required Mechanism Change 必须明确：

* 当前导致 Failure 的关系、状态、信息结构或计算结构；
* 必须发生什么改变；
* change direction；
* causal position；
* activation condition；
* 为什么该改变能够解除 Root Cause。

进一步形成：

Root Cause
→ Required Mechanism Change
→ Required Capability
→ Design Obligations

---

3. 为什么会想到这个 Source Mechanism

---

必须重建：

Target Root Cause
→ Required Mechanism Change
→ 为什么会想到这个 Source Mechanism

重点不是记录“用了什么方法”。

而是搞清楚研究者从目标问题走向源机制时，中间的认知桥梁是什么。

例如可能来自：

* 相同的信息缺失结构；
* 相同的不可观测性；
* 相同的约束结构；
* 相同的因果关系；
* 相同的状态别名问题；
* 相同的优化困难；
* 相同的干预目标。

核心搜索问题是：

> **哪个已有机制已经成功改变了我这里必须改变的 causal/computational variable？**

Principle Search 必须真实覆盖：

1. first-principles derivation；
2. problem representation transformation；
3. same-field mechanisms；
4. cross-domain structurally-isomorphic problem–intervention pairs。

**跨领域搜索必须真实执行，但允许结论为“未发现可信同构”；不得强行制造 analogy 或强制采用跨领域候选。**

这一步最终要回答：

> **Auto Research 以后应该怎样主动寻找强源方法，而不是随机搜索算法。**

---

4. 强 Source Mechanism 必须是真正有效的机制

---

需要恢复：

Source Problem
→ Source Intervention
→ Changed Variable / Structure
→ Causal Effect
→ Outcome
→ Assumptions / Boundary

允许迁移的 Source Mechanism 必须同时满足：

* 核心干预机制明确；
* 不是一个宽泛思想；
* 能指出具体改变了哪个 state / relation / information / computation structure；
* 有可信 Evidence 证明该改变导致结果改善；
* 能明确关键 assumptions、activation conditions 和 failure boundaries。

真正迁移的是：

> **方法真正解决问题的机制，而不是方法的表面形式。**

Solution Principle 必须能够脱离具体算法名称进行表达，并回答：

> **在什么条件下，通过什么干预，改变哪个关键关系 / 状态 / 信息结构，为什么能够解除 Root Cause，以及何时失效。**

典型抽象：

Source Method
→ 去除具体算法形式
→ 提取真正起作用的干预机制
→ Solution Principle
→ 再决定目标域如何实现

---

5. 为什么这个 Source Mechanism 真的能够迁移

---

核心不是做形式上的 analogy。

必须证明：

> **Source Intervention = Target Root Cause 真正需要的干预**

即：

> **源方法真正改变的那个关键关系、状态或信息结构，恰好就是目标问题根因要求改变的东西。**

分析至少包括：

Source Root Cause
↔ Target Root Cause

Source Intervention
↔ Target Required Mechanism Change

Source causal path
↔ Target causal path

Source Causal Effect
↔ Target Expected Causal Effect

真正必须一致的是：

> **该机制到底改变了哪个 causal / computational variable，而 Target RCA 是否恰恰要求改变同一个变量。**

因此：

> **真正需要同构的是 intervention structure，不一定是两个领域原来的 problem story。**

---

6. 为什么迁移之后会形成一个新的强 Method

---

必须重建：

Source Mechanism
+
Target Domain Constraints
→
New Method Structure

Target Domain 可能提出：

* observability；
* dynamics；
* geometry；
* interaction；
* feedback；
* partial information；
* embodiment；
* real-time；
* data / measurement；
* optimization；
* safety / physics；
* closed-loop requirements。

必须分析：

Source Assumption
× Target Constraint
→ Observable Consequence
→ Required Repair / Claim Restriction

所有真实 Assumption–Constraint Collision 必须闭合。

目标域可能迫使 Source Mechanism：

* 重新定义状态；
* 改变信息流；
* 改变作用对象；
* 改变优化变量；
* 增加必要约束；
* 改变决策接口；
* 改变在线估计方式；
* 改变因果作用位置；
* 形成源领域原本不存在的新结构。

目标域改造的价值取决于是否解决真实 Target Constraints，而不是改造数量本身。

---

7. Natural Derivation

---

最后把 Source-domain story 全部删掉。

只看：

Target Failure
→ Target Root Cause
→ Required Mechanism Change
→ Target Constraints
→ Final Method

问：

> **从目标问题自身的 Root Cause 出发，这个方法是否仍然显得必要、自然、无冗余？**

真正好的迁移应该最终呈现成：

> **方法像是从目标 Root Cause 自然推导出来的。**

源领域只负责告诉研究者去哪里发现这个解决机制。

======================================================================
二、什么样的 Method 才真正达到顶会顶刊级
========================

核心假设：

> **强源方法 + 真实同构 + 非平凡目标域改造 + 目标域尚未被已有工作覆盖 → 高概率形成强创新 MethodSeed。**

最终判断的核心不是方法是否“能跑”，而是能否形成真正具有顶会顶刊核心贡献潜力的 Strong Method Seed。

Strong Method Seed 应是一条：

> **最小、可检验的 causal repair program。**

要求：

* 每个核心模块都有 causal parent；
* 核心变化能够写成 `Existing Mechanism → New Mechanism`；
* Target Failure 要求改变的变量、Source 实际改变的变量、Final Method 真实改变的变量一致；
* 所有真实 Target Constraints 和 feasibility debt 都有闭合路径。

---

1. Problem Value

---

研究对象必须是：

* 真实存在；
* 尚未被很好解决；
* 足够重要。

解决该问题必须对目标领域的重要能力、适用边界、可靠性或科学认识产生实质影响。

---

2. Necessity / Simple-Repair Falsifier

---

核心问题：

> **旧机制真的补不上吗？**

在提出新 Method 前，应测试或严谨排除：

* 合理 tuning / gain scheduling；
* 标准 filter / estimator / observer；
* 已知 constraint / certificate；
* 增加数据或模型容量但不改变核心 computation relation；
* 局部 reparameterization；
* strongest baseline；
* 最接近已有机制的公平组合。

如果合理 simple repair 已经覆盖目标 Failure，则新 Method 的必要性不成立。

---

3. Target Intervention Novelty

---

必须证明：

Source Mechanism exists

但：

Target-domain SOTA has not already realized the same causal intervention

Novelty 检查针对 causal intervention / mechanism change，而不是算法名称。

必须检查：

* 同名方法；
* 异名但 causal-equivalent 的 intervention；
* nearest target prior；
* 作者前作；
* Method Genealogy。

Source primitive 已存在并不自动否定创新。

真正需要判断的是：

* Target Intervention Novelty；
* 与 nearest prior 的实质区别；
* Scientific / Mechanism Delta。

---

4. Mechanism Delta

---

进入大规模实验前必须能够写成：

Existing Mechanism / Relation
→
New Mechanism / Relation

可以体现为：

* state representation；
* information flow；
* decision relation；
* optimization variable；
* control interface；
* feedback dependence；
* causal position；
* guarantee quantifier；
* equation / pseudocode / update rule。

Mechanism Delta 必须：

* 具体；
* 可计算或可明确描述；
* 能与 nearest prior 对照；
* 能追溯到 Required Mechanism Change。

不能只写：

“A + B + C 提升 robustness / adaptability / uncertainty awareness。”

---

5. Scientific Delta

---

Scientific Delta 与 Performance Gain 分开判断。

核心问题：

> **相对于最接近的已有工作，这个 Method 对目标问题新增了什么可验证、可归因的科学内容？**

Scientific Delta 可以表现为：

* 新科学知识；
* 新机制；
* 新 Solution Principle；
* 新 representation；
* 新 causal relation；
* 新 applicability boundary；
* 此前无法建立的重要能力。

Performance 更高、模块更多、实现更复杂、使用热门 primitive，均不能单独构成 Scientific Delta。

Scientific Delta 与 Principle 的真实性 / 问题解决能力必须分别判断：

> **能解决任务 ≠ 值得作为顶会顶刊核心科研贡献。**

阶段语义：

Provisional Scientific Delta：
如果 Candidate Principle 成立，它可能增加什么新的科学认识、机制、表示、边界或重要能力。

Final Scientific Delta Claim：
Final Method 准备主张什么新的知识、机制、Principle、表示、边界或重要能力。

Established Scientific Delta：
只有 Full Causal Validation = VALIDATED 后才能形成。

---

6. Causal Coherence

---

必须满足：

# Target Required Structural Change

# Selected Principle / Source Intervention

Final Method Real Computational Change

---

7. Minimality / No Method Soup

---

Final Method 应表示为：

Primary Root Cause
→ Core Intervention
→ Target Incompatibility
→ Repair
→ New Bottleneck
→ Repair
→ ...

每个核心模块必须有 causal parent。

新增模块只能来源于：

1. Primary Root Cause；
2. Target Constraint；
3. Earlier Design 引入的新 incompatibility。

要求：

number of unjustified modules = 0

No-Orphan-Module 是必要条件，但不能单独证明顶会顶刊级创新。

---

8. Natural Derivation

---

删除 Source-domain story 后：

Target Failure
→ Root Cause
→ Required Change
→ Target Constraints
→ Final Method

仍然必须自然闭合。

---

9. Feasibility

---

至少检查：

* required state 是否 observable / estimable；
* estimation error 是否可接受；
* optimization / inference 是否可解；
* computation / real-time；
* closed-loop / stability；
* safety / physics；
* data / hardware；
* validation path。

允许：

Strong Research Seed + Explicit Unresolved Debt

但致命 feasibility debt 不能直接破坏核心 Method Seed。

---

10. Top-Venue Method Strength

---

> **Valid Method Seed ≠ Top-Venue Strong Method Seed。**

顶会顶刊级 Strong Method Seed 必须综合满足：

* Problem Value；
* Necessity；
* Target Intervention Novelty；
* Mechanism Delta；
* Scientific / Conceptual Delta；
* Closest-Prior Separation；
* Causal Coherence；
* Minimality；
* Natural Derivation；
* Feasibility；
* Discriminative Validation。

最终必须真正区分：

普通方法迁移 / application / method soup

与

顶会顶刊级 Strong Method Seed。

======================================================================
三、如何用真实顶级论文验证上述科研过程和标准
======================

最终科研标准不能靠理论上“应该如此”确定。

必须：

> **多篇顶级成功案例 + 同路径近失败案例 + 必要的反事实证据 → Cross-Case Causal Induction**

---

1. 逆向分析必须恢复 Method Genesis

---

不能简单总结：

问题是什么
→ 方法是什么
→ 实验怎么样

必须恢复：

最终 Method
← 目标域必要改造
← 被迁移的核心机制
← Source Method
← Source Problem / Root Cause

并从 Target Problem 正向验证完整形成链。

---

2. 必须追踪 Method Genealogy

---

很多论文不会直接说明进行了方法迁移。

因此必须追：

Target Paper
→ 直接方法前驱
→ 核心机制来源论文
→ 必要时继续追到原始 Source

至少结合：

* Citation Graph；
* Related Work；
* Method Equations；
* Architecture / Formulation Lineage；
* 作者早期工作；
* Source Method 原始论文。

最终确定：

> **目标论文真正借鉴/继承的是哪个核心机制；该机制最初是为了解决什么问题产生的；目标论文到底保留了什么、改变了什么。**

---

3. 区分论文叙事与可支持的 Formation Logic

---

证据强度分为：

E1：原文显式证据
论文明确陈述来源、Failure、assumption、limitation 或 extension relationship。

E2：结构性重建
能够从公式、引用谱系、方法结构、作者前作、ablation、naive variant 等可靠恢复。

E3：历史猜测
关于作者真实构思顺序的推测。

没有真实 genesis Evidence 时，只能说：

> **该论文最终方法具有这样的 causal formation logic。**

不得把推测写成作者真实构思历史。

---

4. 案例必须包含成功、近失败与反事实

---

优先选择高信息量案例：

* RCA-transfer 强成功案例；
* Alignment 成立但 Target Intervention 已覆盖的案例；
* 直接迁移即可成立的案例；
* Target Constraints 迫使关键改造的案例；
* 合理迁移但只有 application 强度的案例；
* Simple Repair 已经解决 Failure 的案例；
* Method 很新但 feasibility 未闭合的案例；
* naive variant / failed design / ablation；
* 其他 formation logic 的顶级论文作为对照。

不同论文允许不同 formation logic。

不强行给每篇论文制造 Source Method、Root Cause 或迁移故事。

---

5. Cross-Case Causal Induction

---

跨案例最终归纳：

Necessary Conditions：
顶级成功案例基本都满足，缺失后近失败案例明显增多。

Non-Necessary Conditions：
部分强案例可以不存在，因此不能写成硬规则。

Insufficient Conditions：
某条件即使满足，仍可能只是普通迁移或 application。

Interaction Conditions：
只有多个条件共同满足时才稳定产生 Strong Method Seed。

最终科研标准必须建立在跨案例证据上，而不能由单篇论文主观总结。

======================================================================
四、实现上述科研逻辑所需的具体流程机制
===================

以下机制只服务于前述 Strong Method 形成逻辑和顶会顶刊级判断。

整体流程：

Failure Activation
→ Operating Envelope
→ Simple-Repair Falsifier
→ Mechanism-Level RCA
→ Required Mechanism Change
→ Required Capability / Design Obligations
→ Source Mechanism / Solution Principle Search
→ Source Genealogy & Causal Efficacy
→ Intervention-Level Alignment
→ Target Intervention Novelty
→ Candidate Solution Principles
→ Provisional Scientific Delta
→ Discriminating Prediction / Killer Test
→ Human Gate
→ Evidence Update / Principle Convergence
→ Selected Principle
→ Assumption–Constraint Collision
→ Minimal Faithful Target Realization
→ Principle-Only Closure
→ Residual MUST
→ Minimal Necessary Composition
→ Causal Repair DAG
→ Mechanism Delta
→ Final Target-Intervention Novelty Closure
→ Natural Derivation
→ Feasibility Closure
→ Counterfactual Necessity Package
→ Final Scientific Delta Claim
→ Top-Venue Method Strength Gate
→ Seed Acceptance / NO-GO
→ Full Causal Validation
→ Established Scientific Delta

---

1. Candidate Solution Principles

---

Candidate Principle 必须是算法无关的 Solution Principle，而不是完整 Method。

每个 Candidate Principle 至少明确：

* 对应 Required Mechanism Change；
* Required Capability / Design Obligations；
* Principle 与 causal mechanism；
* critical / fatal assumptions；
* activation / failure conditions；
* target-domain operationalization；
* Provisional Scientific Delta；
* discriminating prediction；
* cheapest informative / killer test。

Principle Competition 仅在 solution space 欠约束时执行。

Candidate 数量不机械固定，也不能因为找到第一个可行候选就过早关闭搜索。

---

2. Discriminating Prediction / Killer Test

---

Test 必须能够区分不同 Principle、Rival Principle、Primary RCA 或 Rival RCA。

形式：

如果 P 成立
→ Observable Y 应出现 Pattern A。

如果 Rival P' 成立
→ Observable Y 应出现可以区分的 Pattern B。

普通 performance ablation 不自动构成 discriminating test。

---

3. Human Gate / Evidence Update / Principle Convergence

---

现实 Test 在 Human Gate 批准后执行。

Evidence 可以改变：

* Principle confidence；
* assumptions；
* applicability boundary；
* Target operationalization；
* Source–Target mapping；
* Rival RCA；
* Root Cause。

阴性结果只有在：

* Principle 被忠实 operationalize；
* Test 有足够 discriminativeness；
* activation conditions 成立；

时，才能真正削弱或淘汰 Principle。

Evidence 收敛后形成 Selected Principle。

---

4. Method Adaptation 与 Residual MUST

---

Selected Principle 首先形成 Minimal Faithful Target Realization：

* 保留真正起作用的 intervention；
* 去除只服务于 Source task 的实现；
* 只加入 Target 必需结构。

先尝试 Principle-Only Closure。

只有存在真实 Residual MUST 时才允许加入 supporting mechanism。

---

5. Causal Repair DAG

---

Final Method 必须能够表示为最小 Causal Repair DAG。

每个模块均必须有 causal parent；
每条关键 edge 都必须能够设计验证；
不得用模块数量代替 innovation。

---

6. Counterfactual Necessity Package

---

根据 Method 选择最小必要反事实：

* strongest baseline；
* simple repair；
* old mechanism without required change；
* naive Source transfer；
* wrong target representation；
* no-repair variant；
* nearest equivalent prior；
* Rival RCA / Rival Principle prediction。

目的：

> **证明为什么旧机制补不上，以及为什么 Proposed Intervention 在正确 causal position 上补上了。**

---

7. RCA Reopen / Recovery

---

Method Design 允许根据新 Evidence 回退。

包括：

* Test 无辨识力 → 重做 Test；
* Target operationalization 错误 → 重做 mapping；
* Source 不匹配 → 换 Source；
* Principle 不成立 → 换 Principle；
* Required Mechanism Change 不成立 → 返回 RCA；
* causal premise 不足 → reopen Root Cause Analysis；
* Target Intervention 已覆盖 → 重新寻找 Principle / Delta；
* Fatal feasibility debt → repair、限制 claim 或 NO-GO。

---

8. Full Causal Validation

---

最终验证要求：

predicted mechanism change
→ observed mechanism change
→ discriminating evidence
→ performance consequence

Performance improvement 本身不能构成 VALIDATED。

只有：

Full Causal Validation = VALIDATED

之后才能形成：

Established Scientific Delta。

======================================================================
五、Phase II：转化为 Method Design Harness
====================================

Phase I 的科研流程和标准冻结后，再进行 Harness 工程化。

每一步必须压成：

Input
→ Cognitive Operation
→ Required Evidence
→ PASS
→ FAIL
→ Recovery

要求：

Agent 可执行
→ Reviewer 可判断
→ Validator 可检查
→ Gate 可阻断
→ 失败可回退。

1. Input

明确该步骤需要什么 Evidence 和 upstream scientific conclusions。

2. Cognitive Operation

明确 Agent 实际执行什么认知操作，不能只写：

“分析”
“思考”
“判断是否合理”
“寻找创新点”。

3. Required Evidence

科研结论必须可以保存、追溯和复查。

不能只依靠 Agent 声称：

“我认为同构”
“我认为创新”
“我认为这个 Root Cause 正确”。

4. PASS / FAIL

每一个核心科研标准都必须有可观察 PASS / FAIL 条件。

Critical Gate FAIL：

→ 返回对应科研步骤；

或：

→ METHOD_SEED_REJECT / NO-GO。

不能用 weighted score 抵消关键科研硬门失败。

5. Recovery

每个 FAIL 必须明确：

* 返回哪个步骤；
* 补什么 Evidence；
* 重做哪个认知操作；
* 是否换 Source；
* 是否换 Principle；
* 是否 reopen RCA；
* 是否限制 claim；
* 是否淘汰 Method Seed。

6. 全链路真实消费

Harness 必须保证：

Accepted Root Cause
→ Required Mechanism Change
→ Required Capability / Design Obligations
→ Candidate Principle
→ Selected Principle
→ Target Adaptation
→ Final Method
→ Validation Obligations

能够逐级回溯。

科研标准不能只存在于 Prompt、Skill、Schema 或 Artifact 名称中，而必须真实改变 Agent 后续 Method Design。

======

对于当前重点研究的 Failure / RCA + Mechanism Intervention / Transfer 路径：

→ **Top-Venue-Potential Strong Method Seed**

# Target Required Structural Change

Final Method Real Computational Change

最终目标：

**挑选顶级案例 → 重建真实方法生成过程 → 追踪源方法谱系 → 深挖“根因—源机制—同构—目标域改造—最终方法”链条 → 比较成功与近失败案例 → 归纳科研规律 → 转成机器可判定的 Harness 标准。**

真正要回答的是：

> **顶刊级强 Method 是如何从一个真实 Root Cause 出发，通过发现、选择、迁移并改造一个强源机制，自然生长出来的；以及每一步怎样判断做对了。**

最终使 Auto Research 能够真正设计出达到顶会顶刊标准的方法。
