1）handoff和原对话里面说的很清楚，究竟什么是从失败中找问题并分析根因+通过方法迁移解决问题。换句话说，就是先找到问题，然后用一些方法搞清楚问题根因，然后进行方法迁移，仔细捋一遍，分析 “从失败中找问题并分析根因+通过方法迁移解决问题”这一套流程到底是怎么走的，步骤是什么，每一步的标准是什么，不能是模糊的标准，因为这最终要转化为harness，进行auto research的！ 

2）而且，其实很多文章都这么干的，但文章不会明说他们是用的方法迁移，他们往往会弱化这一点，但是可能可以检索到他们借鉴的方法的文章 ，所以不要死板的看文章说什么就信什么， 

3）强源方法+真实同构+非平凡目标域改造+目标域尚未被已有工作覆盖->高概率形成强创新MethodSeed(方法种子)

4）真正要逆向恢复的是 Method Genesis，而不是“论文最后用了什么方法”：失败 → 根因 → 需要改变什么机制 → 为什么想到这个源机制 → 为什么它能迁 → 为什么必须这样改造 → 最终 Method，尤其必须回答三个“为什么”——为什么想到它、为什么逻辑上能迁、为什么迁移后会自然形成一个新的强方法。

5）“真实同构”不能是表面 analogy，而必须满足：Source Root Cause ↔ Target Root Cause、Source Intervention ↔ Target Required Mechanism Change、Source causal path ↔ Target causal path；核心判断就是原话里的：Source Intervention = Target Root Cause 真正需要的干预。

6）最终标准不能提前拍脑袋冻结，必须通过“多篇顶级成功案例 + 同一路径近失败案例”做跨案例归纳，区分“普通方法迁移 vs 顶刊级方法迁移”，最后把结论压成 Agent 可执行、Reviewer 可判断、Validator 可检查、Gate 可阻断的硬标准，而不是“要创新、要同构、要非平凡改造”这种模糊科研经验。

7）逆向分析顶会顶刊时，不同论文思路可能完全不同。不要为了填统一模板而强行给论文制造 Source Method、Root Cause 或迁移故事等内容。寻找大部分/部分论文的共性和规律即可，而不是要求每篇文章完全满足预设理论。

总纲：
先研究清楚“如何从真实失败中发现问题并得到机制级根因，再由根因推出所需机制改变，主动发现强源机制，验证因果同构，完成目标域驱动的非平凡改造，并形成目标域尚未覆盖、且能从 Root Cause 自然生长出来的 Strong Method Seed”，然后用真实顶级案例与近失败案例把这套科研过程固化成不模糊的 Harness 标准。

你的要求可以归纳成下面 **9 个核心要求**。前 5 个是科研能力本身，后 4 个是 Harness 实施与提示词约束。

1. **最终目标只有一个：Method Design 必须能产出真正具有顶会顶刊潜力的方法。**
   不是“流程完整”“字段齐全”“看起来创新”，而是方法必须针对重要真实问题、解决真正机制瓶颈，并形成足够强的 Scientific Delta（科学增量）。

2. **第一核心能力：必须真的能从 Failure（失败）分析出机制级 Root Cause（根因）。**
   不能停在“固定阻抗不好”“泛化差”“不够自适应”等表层描述；必须经过 Simple Repair（简单修复）排除后，对 residual failure（残余失败）继续追到具体 causal/computational relation（因果/计算关系），而且要可证伪、可干预、有竞争解释，不能先想方法再倒推根因。

3. **第二、也是更关键的能力：必须真的能主动找到其他领域的方法迁移机会。**
   核心不是“搜相似算法”，而是：
   `RMC → 发现其他领域 → 学习当地术语 → 找真实 Problem–Intervention Pair（问题—干预对）`。
   Harness 必须自己完成这个发现过程，而不是靠你提前告诉它哪个领域、哪篇论文、哪个方法。

4. **跨领域迁移必须经过真正的机制同构判断。**
   找到 Source 后不能因为任务相似、算法相似、关键词相似就迁移。必须验证：
   `Source Intervention 实际改变的机制`
   是否正好对应
   `Target RMC 必须改变的机制`，
   包括变量/关系、改变方向、因果位置、激活条件和实际效果。

5. **迁移后必须自然化，而不是“搬方法”或“拼模块”。**
   真正迁移的是 Solution Principle / causal mechanism（解决原理/因果机制），然后根据 Target Constraints（目标约束）只做必要改造。删除 Source 故事以后，仍应能从：
   `Target Failure → RCA → RMC → Target Constraints → Final Method`
   自然推出最终方法。没有真实约束冲突就不能为了“创新”硬加模块。

6. **流程不能退化成 LLM 自己的头脑风暴。**
   Scientific Prior 只能产生搜索假设，不能当证据；First-Principles（第一性原理）和 Representation Transformation（表示变换）也必须留下可审查推导，而不能靠几段自然语言自圆其说。关键科研结论必须经过 Evidence + Reviewer + Gate，而不是“LLM 觉得合理”。

7. **绝对不过度设计。**
   这是个人科研 Harness，只实现科研流程和科研正确性所必需的东西。不要新增安全系统、权限系统、通用 Agent framework、第二套 Evidence/Search/Source/Experiment 系统、未来预留抽象、兼容层或无关重构。

8. **所有修改必须遵守你指定的 Editing discipline。**

   * **Surgical editing**：只改目标所需内容，无关正确内容保持不变。
   * **Minimal sufficient change**：做最小但完整的修改，不顺手扩展、清理、重构。
   * **Target-state editing**：旧抽象错了就直接替换成最终正确状态，不保留旧/新双轨、迁移叙事或 fallback。

   同时提示词本身也要遵循：**准确、完整、最短充分；目标、修改内容、约束、验收标准、验证方式颗粒度对齐，无遗漏、无冲突、少重复。**

9. **最终验收必须证明 Harness“自己会做”，不能只证明代码和 schema 能承载正确答案。**
   必须做不预置答案的 Scientific Capability E2E（科研能力端到端测试）：不给 RCA、RMC、候选领域、目标 Source、Solution Principle、Final Method，让 Harness 自己完成：
   `Failure → RCA → RMC → 跨域发现 → Problem–Intervention Pair → 同构判断 → Principle → 自然化方法`

   并且必须能拒绝：

   * 表层 RCA；
   * Simple Repair 就能解决的伪创新；
   * surface analogy（表面类比）；
   * 直接搬 Source；
   * 有效但不够顶会顶刊级的方法。

再压成一句话，你真正要求的是：

> **把 ARIS 改成一个受 Evidence、Reviewer 和 Gate 约束的科研 Method Design Harness：它必须自己从真实失败追出机制根因，再主动到其他领域找到真实问题—干预对，证明干预机制与目标 RMC 同构，将原理自然迁移回来，并最终只接受真正具有顶会顶刊潜力的方法；整个实现必须最小、直接、无过度设计，不能退化成 LLM 头脑风暴。**
