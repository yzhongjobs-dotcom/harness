1. 修改边界与总体目标状态
======================================================================

1.1 必须保持不变

除为实现冻结科研标准所必需的直接依赖外，不重构：
- Controller 通用架构；
- Evidence Registry / Literature Corpus / Search Ledger；
- 现有 literature provider、admission、full-text、Evidence Card 流程；
- review attestation、reviewer independence、Human receipt；
- append-only scientific history；
- Candidate Human Selection 与 Principle Test Human Approval 的现有职责；
- user-initiated Full Validation 入口；
- generic workflow migration 模型。

不建立：
- 第二套 evidence/search system；
- compatibility/fallback 双轨；
- E2E 专用 migration 分支；
- weighted scientific score；
- 与本任务无关的权限、安全、通用 agent framework 或重构。

1.2 新版真实 workflow

目标主链：

problem_generation
→ problem_quality_gate
→ problem_novelty_gate
→ problem_human_acceptance
→ problem_necessity
→ root_cause_analysis
→ root_cause_gate
→ method_design
→ principle_human_selection
→ principle_test_design
→ principle_test_human_approval
→ principle_evaluation
→ method_refinement
→ final_method_novelty_gate
→ top_venue_method_strength_gate
→ final_method_human_acceptance
→ user-initiated Full Causal Validation

仅新增两个必要 formal phase：
1. problem_necessity：补齐 pre-RCA Failure/Envelope/Simple-Repair Necessity hard gate；
2. top_venue_method_strength_gate：补齐 Final Method 的顶会顶刊级科研强度硬门。

其余科研机制优先在现有 phase、artifact、review、return、literature gateway 中补齐，不另建平行流程。

1.3 Harness 职责边界

所有核心科研步骤必须形成：
Input → Cognitive Operation → Required Evidence → Reviewer Judgment → PASS/FAIL → Recovery → Downstream Consumption。

- Main/Agent：执行科研认知并生产 scientific artifact；
- Reviewer：判断因果、机制、创新、必要性、可行性等科学语义；
- Validator：只检查 schema、ID/ref/hash、覆盖关系、DAG/引用/状态等机械事实；
- Controller：绑定输入、审核身份与 hash、执行 Gate/return/invalidation/terminal transition；
- Human：只承担已声明的 Human Gate，不替代 Reviewer。

2. Phase 0：当前 E2E 的正式预处理（必须先于任何 Harness 修改）
======================================================================

目的：把当前 E2E 的 executed prefix 正式退回到新版仍可兼容的位置，避免修改 method_design/root-cause 语义后 generic migration 因 executed phase spec 变化而拒绝迁移。

严格顺序：

1. 使用现有 save-recovery 保存当前 E2E State、workflow identity、关键 artifact hashes 与 history，作为操作前恢复快照。
2. 用户在当前 principle_selection Human Gate 作出真实 request_revision，理由明确为：旧 Method Design 不满足已冻结的新科研标准，需要重新执行。
3. Controller 按现有 return/invalidation 机制返回旧 method_design；不得手改 State。
4. 启动旧 method_design，使其进入 running。
5. 使用现有 reopen-root-cause，以“缺少 pre-RCA necessity/residual-envelope closure”为科研理由正式返回 root_cause_analysis。
6. 核验：
   - accepted Problem、Field Map、Contract、Capsule、Evidence/history 仍有效；
   - 旧 RCA、RCA verdict、Method Design 及全部下游 active artifacts 已归档/失效；
   - current scientific prefix 只保留 through problem_human_acceptance。
7. 完成以上状态预处理后，才允许修改 Harness。

禁止：
- 伪造 Human receipt；
- 直接编辑 .aris/runs/*.json；
- 把旧 Candidate/Route 转成新版 Candidate Principle；
- 自动继承旧 RCA 或 Method Design 科研判断。

3. Stage 1：冻结新版 workflow、artifact contracts 与 Controller 基础语义
======================================================================

目标：先定义唯一 canonical target state，再修改生产/消费逻辑，避免 schema 与运行路径漂移。

3.1 Workflow

修改 skills/shared-references/idea-workflow.yaml 及 canonical mirror：
- 在 problem_human_acceptance 与 root_cause_analysis 之间插入 problem_necessity；
- 在 final_method_novelty_gate 与 final_method_human_acceptance 之间插入 top_venue_method_strength_gate；
- 更新 scientific_core.phases、allowed_agents、artifact manifest/contracts、required inputs、return targets、validation handoff inputs；
- 保持既有 Human Candidate/Test Gate 语义不变。

3.2 新增/调整 machine authority

新增：
- idea-stage/NECESSITY_CLOSURE.json
- idea-stage/NECESSITY_VERDICT.json
- idea-stage/NECESSITY_TEST_EVIDENCE.jsonl
- refine-logs/FINAL_METHOD_PACKET.json
- idea-stage/TOP_VENUE_METHOD_STRENGTH_VERDICT.json

权威关系：
- NECESSITY_CLOSURE.json：pre-RCA necessity scientific artifact；
- NECESSITY_VERDICT.json：独立 reviewer verdict；
- NECESSITY_TEST_EVIDENCE.jsonl：Controller-owned、append-only 的 Necessity test lifecycle/execution/evidence ledger；它保存 test specification 注册、必要的执行批准、handoff 与 terminal result 历史，只证明正式生命周期中执行了什么以及得到什么结果，不是 Necessity 科学结论权威；
- FINAL_METHOD_PACKET.json：Final Method 唯一机器权威；
- FINAL_PROPOSAL.md：由 FINAL_METHOD_PACKET 确定性渲染的人类视图，不再作为机器事实来源；
- TOP_VENUE_METHOD_STRENGTH_VERDICT.json：顶会顶刊级最终科研硬门 verdict。

保留现有 REFINE_STATE.json 作为 refinement/review progress state；它继续服务 resume/progress，但不得与 FINAL_METHOD_PACKET 形成第二套 Final Method authority。

3.3 全局 Scientific NO-GO

增加唯一 Controller terminal：
scientific_core.status = SCIENTIFIC_NO_GO

只允许以下已经具备明确不可修复语义的 Critical Gate 触发：
- method_refinement：fatal feasibility debt 无法 repair 或 claim-restrict，且直接破坏核心 seed；
- top_venue_method_strength_gate：critical failure 在批准 scope 内不存在合理 fixed-return recovery，且所有可行的 Principle/RCA/Necessity/Problem/Claim 修复路径均已由 Evidence 排除。

没有找到可信 Principle 不构成不可修复性的证明，必须继续 Search 或返回 RMC/RCA/Necessity。只有 Evidence 证明核心要求在批准约束下不可实现，且所有合理 fixed-return recovery 均已排除时，才允许 NO-GO。

保存唯一 no_go_record：no_go_id、subject_type、subject_id、source_phase、verdict/reviewer、reason_code、evidence_refs、reviewed artifact hashes、excluded_recoveries[]、scientific rationale、terminated_at。

允许触发 NO-GO 的 Gate 在 workflow spec 中使用独立 `terminal_verdicts: {NO_GO: SCIENTIFIC_NO_GO}`；NO_GO 不进入普通 `return_targets`。Controller-issued review request 的 allowed verdicts 由 accepted_verdicts、return_targets 和 terminal_verdicts 的并集形成。phase 完成且 attested reviewer verdict 为 NO_GO 时，allowed action 只开放 `terminate_scientific_core`；Controller 校验 live request、review attestation、reviewed hashes 与完整 no_go payload 后，materialize no_go_record 并执行统一 terminal transition。Reviewer 提供 reason_code、Evidence refs、excluded recoveries 与 scientific rationale；Controller 生成 ID/时间并绑定 subject、source phase、verdict/reviewer 和 reviewed hashes。

进入 SCIENTIFIC_NO_GO 后：
- current_phase = null；
- 不创建 validation entry，不允许 validation handoff；
- allowed scientific actions = none；
- 当前 seed/run 正式结束，history/archive 保留。

默认可修复失败仍走固定 return，不得滥用 terminal。

problem_necessity 的 FULLY_COVERED 默认返回 problem_generation 重新选问题，并通过 return_history + archive bindings 持久记录 no-new-method-needed；它不自动写成 Method Seed rejection。

4. Stage 2：实现 pre-RCA Problem Necessity Hard Gate
======================================================================

目标：在 RCA 前正式证明“目标 Failure 真实存在于 Operating Envelope，且合理 Simple Repair 不能完整闭合目标问题”。

4.1 problem_necessity formal phase

采用现有 method_design 同类 Producer/Reviewer/Controller 模式，不拆成两个 workflow phase：
- Main 产生 NECESSITY_CLOSURE.json；
- independent_problem_reviewer 在 fresh context 审查并产生 NECESSITY_VERDICT.json；
- Controller 绑定 accepted Problem/Contract/Capsule/Evidence hash 后执行 verdict。

扩展 idea-creator 为 necessity mode；扩展 independent_problem_reviewer 支持 necessity request，复用现有 reviewer role，不增加新 reviewer backend。

4.2 NECESSITY_CLOSURE 必须表达

- problem binding；
- active_failures[]：failure_id、condition、observable failure、consequence、evidence refs；
- operating_envelope；
- simple_repair_assessments[]：具体 repair、evidence、coverage boundary、结论；
- necessity_test_evidence_refs[]：只引用当前 Problem/version 下已经达到 terminal outcome 的 Necessity test lifecycle records/result artifacts；
- residual_failure_envelope；
- proposed problem-identity disposition。

Simple Repair 至少检查冻结标准要求的合理类别：
- tuning / gain scheduling；
- standard filter / estimator / observer；
- known constraint / certificate；
- more data/capacity without changing the core relation；
- local reparameterization；
- strongest baseline；
- nearest fair combination。

4.3 Reviewer verdict 与 Controller 固定消费

允许：
- FULLY_COVERED
- RESIDUAL_SAME_PROBLEM
- RESIDUAL_REDEFINES_PROBLEM
- UNRESOLVED

Controller：
- FULLY_COVERED → 返回 problem_generation；当前 Failure 不再支持“需要新 Method”的主张；
- RESIDUAL_SAME_PROBLEM → accept necessity，进入 RCA；
- RESIDUAL_REDEFINES_PROBLEM → 返回 problem_generation，必须重新经过 quality、novelty、Human acceptance；
- UNRESOLVED → 返回 problem_necessity，补 Evidence/分析。

Partial repair 不能只写“部分有效”：必须显式形成 Residual Failure Envelope，并判断 residual 是否仍属于同一 accepted Problem。

4.4 Evidence recovery

problem_necessity 必须支持两类 current Evidence：
1. 已有正式 Evidence、dataset、experiment 或 real-world artifact；
2. 现有 Evidence 无法严谨裁决时，新执行的最低成本 empirical/analytical necessity test。

文献不足时，把 problem_necessity 加入现有 incremental literature gateway 的 permitted phase；query context 必须绑定当前 Problem/Contract/Capsule 与具体 failure/simple-repair decision target。

目标域 empirical/analytical test 采用同一 phase 内的 Controller-bound 路径：

necessity decision target
→ register test/analysis specification
→ Controller handoff
→ execution/result artifact
→ Controller normalization
→ NECESSITY_TEST_EVIDENCE.jsonl
→ NECESSITY_CLOSURE.json
→ independent review
→ NECESSITY_VERDICT.json

NECESSITY_TEST_EVIDENCE.jsonl 是 specification 到 result 的唯一持久化 lifecycle ledger，不另建 Test Plan artifact。event_type 只允许：
- TEST_SPEC_REGISTERED；
- EXECUTION_APPROVED（仅在该执行需要显式 Human initiation/approval 时）；
- EXECUTION_HANDED_OFF；
- RESULT_AVAILABLE；
- NO_RESULT。

所有 event 共同绑定 event/test ID、active Problem ID/version、failure ID、repair ID、coverage decision target、specification hash、前序 event refs、recorded_at 与 current phase/problem/version。event-specific payload：
- TEST_SPEC_REGISTERED 保存完整 specification、所需 Evidence、最低成本/信息增益理由与 specification hash；
- EXECUTION_APPROVED 保存绑定 live specification/handoff scope 的 Human receipt；
- EXECUTION_HANDED_OFF 保存 Controller-issued handoff ID/hash；
- RESULT_AVAILABLE / NO_RESULT 保存 terminal outcome、execution/result artifact hash 或 no-result reason、provenance 与 Evidence refs。

NECESSITY_CLOSURE 不保存或批准待执行 test plan，只在所有被其引用的 Necessity tests 已 terminal 后形成，并仅消费 current terminal records/result artifacts。若仍需新测试，Main 先注册新 specification 并完成上述生命周期，再重新形成 Closure。

历史 ledger 中存在记录不代表它自动成为当前 Necessity Closure 可用 Evidence；必须满足 Evidence currentness 和当前 phase/problem/version binding。低成本本地分析可在 Controller handoff 后执行；涉及真实实验、外部系统或实质成本时必须有显式 user initiation/approval，但不新增 workflow phase。

不新增 provider、corpus 或 Evidence Registry；NECESSITY_TEST_EVIDENCE.jsonl 只承担 phase-bound execution/evidence history，不与 NECESSITY_CLOSURE/VERDICT 形成第二套科研结论权威。

4.5 RCA 新前置绑定

root_cause_analysis required inputs 增加 accepted NECESSITY_CLOSURE/VERDICT。
RCA machine artifact增加 necessity_binding（closure/verdict ID/hash、residual failure/envelope refs）。
Validator 检查引用/hash/ID闭合；Root-Cause Reviewer 判断 RCA 是否科学上解释 residual failure，而不是原始已被 Simple Repair 覆盖的 failure。

5. Stage 3：补齐 RCA → RMC → Capability → Obligation 的真实机器链
======================================================================

目标：Required Mechanism Change 必须从 accepted residual RCA 推出，并成为后续搜索、Candidate、Test、Final Validation 的真实输入。

5.1 RMC 定义

修改 METHOD_DESIGN_PACKET contract：每个 RMC 至少包含：
- mechanism_change_id；
- causal_chain_ids；
- failed_relation_state_or_information_structure；
- required_mechanism_change；
- change_direction；
- causal_position；
- activation_condition；
- root_cause_resolution_rationale；
- capability_ids；
- obligation_ids。

删除 RMC 自身的 acceptance_conditions 作为科研定义字段；可观察 PASS/FAIL 单独作为 validation obligation/Capability/Obligation contract 表达。

5.2 Primary-chain disposition

新增显式 primary_chain_dispositions：每条 accepted primary causal chain 必须且只能被处置为：
- RMC：由一个或多个 RMC 消费；
- CLAIM_BOUNDARY / OUTSIDE_FINAL_CLAIM_ENVELOPE。

CLAIM_BOUNDARY 必须有 Evidence/rationale，传播到 applicability boundary 和 Final Claim，并在 Top-Venue Gate 重新判断缩小后的 Problem Value；不得作为漏掉 causal chain 的空出口。若 claim boundary 实质改变 Problem identity，必须返回 problem_necessity 或 problem_generation。

accepted primary causal chain 若被发现不属于 accepted residual failure envelope，说明 Necessity/RCA 不一致，必须返回 problem_necessity 或 root_cause_analysis；不得用 disposition 消化。

5.3 Coverage

Validator 机械保证：
- RMC/Capability/Obligation 双向 ID 闭合；
- 每条 primary chain 有 disposition；
- 每个 active Capability/Obligation 被后续 Candidate 消费。

科学上“RMC 是否真的由 RCA 推出”仍由 independent_method_reviewer 判断。

======================================================================
6. Stage 4：重构 Mechanism-Guided Domain Discovery、Source/Principle Search、Genealogy、Alignment 与 Early Target Novelty
======================================================================

目标：Auto Research 必须从 Required Mechanism Change 主动发现其他领域中真正同构的 problem–intervention pair，并以 intervention-level causal alignment 判断能否迁移；不能依赖表面关键词相似、固定领域列表或事后 analogy。

6.1 四类 Principle Search Coverage

对每个 RMC 必须真实覆盖：
1. first-principles derivation；
2. problem representation transformation；
3. same-field mechanisms；
4. cross-domain structurally-isomorphic problem–intervention pairs。

使用 coverage record，不使用固定 query、领域或 Candidate 数量。
一个 search/session 可以服务多个 RMC，只要 binding 清楚。

前两项是 Cognitive Operation，不再伪装成 literature query。
后两项必须有正式 provenance；cross-domain 必须真实执行下述 Domain Discovery → Terminology Grounding → Domain-specific Search，允许结论为 NO_CREDIBLE_ISOMORPHISM_FOUND，但不能用空列表+rationale 代替执行。已有 decision-grade Evidence 足以形成 current coverage 时可显式 re-adopt，不强制重复外部查询。

修改现有 validate_query_plan：
- literature query 不再强制 FIRST_PRINCIPLES / REPRESENTATION_TRANSFORMATION；
- Source literature query 只绑定真正需要检索的 same-field/cross-domain decision target；
- completion 时校验最终 packet 的 RMC、Domain Discovery、terminology/search provenance 与上下文一致；旧 RMC 上下文 Evidence 未 re-adopt 不得自动成为 current Evidence。

6.2 Cross-Domain Domain Discovery 与 Terminology Grounding

在现有 principle_search_record 内增加结构化记录；不新增 workflow phase、artifact、provider、Evidence Registry 或平行搜索系统。

A. Target Mechanism Signature

每个进入跨域搜索的 RMC 必须在对应 Source search 前派生 target_mechanism_signature，至少记录：
- rmc_id；
- domain_neutral_failure_structure；
- causal_or_computational_variable；
- current_relation_or_state；
- required_intervention；
- change_direction；
- causal_position；
- activation_condition。

该 signature 是 Reasoning/Alignment anchor，不要求直接作为跨领域检索关键词。

B. Domain Hypothesis Discovery

每个 RMC 的 cross-domain coverage 必须执行两个互补 discovery channel：

1. MODEL_PRIOR：Main 基于模型已有科研知识提出“哪些成熟领域可能存在同构 problem–intervention pair”，并记录 expected_problem_structure、expected_intervention_family 与 rationale。该记录只是 search hypothesis，不是 scientific Evidence。
2. ACADEMIC_BRIDGE：使用现有正式学术检索/read 能力，从 review/tutorial、已读论文术语、reference/citation chain、以及现有 provider 可获得的 topic/field/related-work metadata 中寻找中间 mechanism/terminology，并据此发现模型先验遗漏的 candidate domain。允许形成 NO_ADDITIONAL_DOMAIN_HYPOTHESIS，但必须有真实 search/read provenance。

PRACTITIONER_SIGNAL 仅在术语不明确、学术搜索陷入局部、问题高度工程化或需要 implementation genealogy 时条件触发。可通过现有可用的 general-web/human-search discovery surface 检查 GitHub、Reddit、StackExchange、X 等专业讨论；结果只能生成 candidate domain / terminology / method-family hypothesis，不作为 Source causal-efficacy 或 alignment Evidence，必须回到正式学术文献验证。不得为此新增专用 provider 或第二套 Evidence system。

每个 domain_hypothesis 至少记录：
- domain_hypothesis_id；
- rmc_id / target_mechanism_signature_ref；
- source_channel：MODEL_PRIOR | ACADEMIC_BRIDGE | PRACTITIONER_SIGNAL；
- domain / research community；
- rationale / structural bridge；
- expected_problem_structure；
- expected_intervention_family；
- provenance/evidence refs（MODEL_PRIOR 可为空并明确标记 hypothesis-only）。

C. Domain Terminology Grounding

对进入正式 Source search 的 candidate domain，必须先用该领域的 review/tutorial/foundational or representative papers 建立 evidence-grounded terminology map，至少记录：
- domain_hypothesis_id；
- canonical_problem_terms；
- canonical_variable/state terms；
- canonical_intervention terms；
- canonical_method_families；
- evidence refs / search-read provenance。

检索词必须优先使用该领域自己的 canonical terminology；Target Mechanism Signature 用于约束语义，不要求一个抽象关键词跨所有领域复用。

D. Domain-specific Problem–Intervention Search 与迭代扩域

基于：
`Target Mechanism Signature + Domain Hypothesis + grounded local terminology`
执行 domain-specific problem–intervention search，寻找真实：
`Source Problem → Source Intervention → Changed Variable/Structure → Causal Effect → Outcome`。

搜索/read 中发现的新术语、mechanism、reference/citation 或 research community 若形成新的高价值 domain hypothesis，必须先以 provenance 注册该 hypothesis，再进行对应 Terminology Grounding 和 Source search。不得在看到 Source 后反向补造其 discovery hypothesis。

cross-domain coverage 只有在以下条件同时满足时才可 closure：
- MODEL_PRIOR 与 ACADEMIC_BRIDGE 两个 mandatory channel 均已执行；
- 所有仍 active 的 candidate domains 均已完成 terminology grounding 与 domain-specific search，或有 Evidence-based closure rationale；
- search 中新产生的高价值 domain branches 已被继续探索或正式关闭；
- 无 unresolved high-value domain branch。

Controller/query-plan context 必须 hash-bind 当前 target_mechanism_signature、domain_hypothesis 与 terminology-map/search target。新发现的 domain hypothesis 必须先注册并绑定 provenance，再允许发起该 domain 的新 query/session。

6.3 Source Mechanism 统一结构

在同一 METHOD_DESIGN_PACKET 中增加 source_mechanisms[]；不创建第二套 registry。
每个 Source Mechanism 至少记录：
- source_mechanism_id；
- discovery_bridge：引用 target_mechanism_signature、domain_hypothesis_id、terminology_map/search provenance，说明该结构桥如何实际导向此 Source；
- genealogy：有序 node → lineage relation → node，每个 node/edge 绑定 mechanism/paper ID 与 Evidence refs；
- 当前认定的 mechanism origin，或停止继续追溯的 Evidence-based rationale；
- Source Problem；
- Source Intervention；
- changed variable/relation/structure；
- causal effect → outcome；
- assumptions / activation / boundaries；
- evidence refs。

Source Mechanism 必须来自正式学术 Evidence；MODEL_PRIOR 或 PRACTITIONER_SIGNAL 只能解释“为何去找”，不能证明 Source causal efficacy。

不把 Phase I 的 E1/E2/E3 Method Genesis 证据等级强制加入常规 Runtime。

6.4 Candidate origin 与 Intervention-Level Isomorphism

Candidate 必须显式绑定：
- source_mechanism_id；或
- first-principles / representation derivation record。

对于迁移型 Candidate，必须结构化保存：
Target Required Change ↔ Source Intervention
并记录 variable/relation 的 causal role、change direction、causal/intervention position、activation condition、causal effect、mismatch 与 target constraints。

核心 hard condition：Source Intervention 实际改变的 causal/computational variable，必须与 Target RCA/RMC 证明必须改变的 variable/relationship 对齐；问题名称、算法形式、共享 buzzword 或表面任务相似不能代替该条件。

Validator 检查 signature/domain/search/source 的引用、hash、provenance 与时序闭合；Reviewer 判断 Source causal efficacy 与 intervention-level isomorphism 是否科学成立。核心映射失败的 Source 不得生成 active Candidate Principle。

6.5 Early Target Intervention Novelty

仍在 method_design 内完成，不新增平行 novelty phase。
每个 active Candidate 在 PRINCIPLE_PACKET_READY 前必须有 current target-intervention novelty closure：
- nearest target priors；
- causal-equivalent intervention check；
- evidence/search provenance；
- uncovered residual delta / covered conclusion。

如需新文献，复用同一 incremental gateway，以独立 target-intervention-novelty search context 绑定当前 Candidate/RMC/intervention；不建立第二套 novelty search system。

目标域已覆盖等价 causal intervention 的 Candidate 不得作为 active Strong Method Candidate 进入 Human selection；应淘汰、降级或重构 delta。

7. Stage 5：Principle Competition、Killer Test、Evidence Convergence 与 Selected Principle
======================================================================

目标：修复当前“Candidate/Test/Evidence 已分层，但竞争解释、判别预测和 Selected Principle 信息闭合不够”的问题；保持现有两个 Human Gate 不变。

7.1 Candidate Principle

METHOD_DESIGN_PACKET 增加 solution_space_constraint_assessment：
- UNDERCONSTRAINED：必须存在多个 intervention mechanism 实质不同的可存活 Candidate；
- CONSTRAINED：允许单 Candidate，但必须有约束依据。

不得固定生成 N 个 Candidate，也不得用 backbone/optimizer/parameter 差异伪造 Principle Competition。

7.2 Discriminating Prediction / Killer Test

Human selection 前，扩展 Candidate `predictions[]`，使每个 Candidate 在 METHOD_DESIGN_PACKET 中保存 killer-test concept：
- observable；
- Candidate Principle 的 Pattern A；
- relevant Rival Principle 或 Rival RCA 的 Pattern B；
- activation condition；
- falsification/killer criterion；
- cheapest-informative rationale。

killer-test concept 不是 concrete test，不包含具体 operationalization、execution requirements、test-only realization、execution set 或 cost。independent_method_reviewer 在 Candidate packet review 中判断它是否真正能够区分 Candidate/Rival，而不把它误判成禁止进入 method_design 的 concrete test。

Human selection 后，principle_test_design 才把选中 Candidate 的 killer-test concept 具体化为：
- operationalization；
- execution requirements；
- test-only realization；
- execution set；
- cost；
- 与 Candidate/Rival Pattern A/B 对应的正式 observation 和 terminal criteria。

Test 的正式 execution target 仍绑定 Human-selected Candidate；Rival 作为比较解释引用，不改变现有 Human Candidate Selection/Test Approval 语义。

仅 performance ablation 不能自动成为 discriminating test。

7.3 Evidence Update

结构化 principle_evaluation 中现有 assessment 列表，使其逐 test/assumption/prediction 可追踪：
- operationalization fidelity；
- test validity；
- activation outcome；
- observed pattern；
- rival discrimination；
- Evidence-driven Principle update。

新增 scientific_updates[]，每条至少包含：
- target_type；
- target_id；
- before；
- proposed_after；
- evidence_refs；
- consequence。

target_type 至少覆盖 Principle、assumption、Source–Target mapping、target operationalization、applicability boundary、Rival Principle、Rival RCA、Root Cause、Necessity/residual envelope。

consequence 只允许：
- REVISE_EVALUATION；
- MORE_EVIDENCE；
- UPDATE_BOUNDARY；
- RETURN_METHOD_DESIGN；
- REOPEN_RCA；
- REOPEN_NECESSITY；
- REDEFINE_PROBLEM。

固定消费：
- 原始 result 有效，仅 interpretation/attribution/evaluation/Evidence-to-claim reasoning 需修正 → REVISE_EVALUATION；保留同一 execution set 和 terminal results，留在 principle_evaluation，不得重跑实验；
- test validity/discriminativeness/activation/operationalization 无效，或需要新 Evidence 才能裁决 fatal assumption → MORE_EVIDENCE；返回 principle_test_design，形成新 minimum test cycle、独立 review 和 Human approval；
- applicability boundary 合理收窄且仍保持 Problem/Principle identity → UPDATE_BOUNDARY；允许继续 convergence，并传播到 Selected Principle、Final Method 和 Claim；
- Source/Principle 被否定 → RETURN_METHOD_DESIGN；
- RMC/Rival RCA/Root Cause 冲突 → REOPEN_RCA；
- residual envelope/Necessity premise 冲突 → REOPEN_NECESSITY；
- Problem identity 实质改变 → REDEFINE_PROBLEM。

Principle Evaluation 只能记录对 accepted RCA/Necessity 的 conflict 或 proposed update；不得原地改写 accepted upstream artifact。真正改变 RCA/Necessity 必须先由 Controller return，再经过对应 phase 的 producer → reviewer → gate。

PRINCIPLE_EVALUATION_VERDICT 的 formal decision enum 与 Controller transition 冻结为：
- PRINCIPLE_CONVERGED → method_refinement；可携带 Reviewer 已接受、且不改变 Problem/Principle identity 的 UPDATE_BOUNDARY，并由 Controller materialize 到 Selected Principle；
- REVISE_EVALUATION → principle_evaluation；
- MORE_EVIDENCE → principle_test_design；
- CANDIDATE_REJECTED → method_design，对应 Source/Principle rejection；
- RCA_CONFLICT → root_cause_analysis，对应 RMC/Rival RCA/Root Cause conflict；
- NECESSITY_CONFLICT → problem_necessity，对应 residual envelope/Necessity premise conflict；
- PROBLEM_CONFLICT → problem_generation，对应 Problem identity/premise conflict，并重新经过完整 Problem Gate 链。

scientific_updates[].consequence 是 Main 的 Evidence interpretation/proposed consequence，不是 Controller transition authority。Independent Reviewer 必须审查这些 updates 并给出上述唯一 formal verdict；Controller 只能消费 attested Reviewer verdict，不能直接按 Main 的 consequence 回退。

阴性结果只有 operationalization faithful、test discriminating、activation成立时才允许真正削弱/淘汰 Principle。

7.4 Selected Principle

Controller materialize 的 SELECTED_PRINCIPLE 必须保留完整 accepted scientific closure，而不只保留 ID 与少量结构：
- Principle/intervention/changed structure；
- RMC/Capability/Obligation/causal-chain bindings；
- Source/derivation binding；
- intervention alignment；
- target novelty closure；
- accepted assumptions/predictions；
- provisional Scientific Delta；
- evidence closure；
- activation/failure/applicability boundaries；
- remaining uncertainty。

只保存已收敛结论，不复制被拒 Candidate 噪声。

8.1 FINAL_METHOD_PACKET.json

- claim-validation obligations；

render_final_method_view(FINAL_METHOD_PACKET)
→ Controller 写入 FINAL_PROPOSAL.md
→ Validator 校验 Markdown 与 packet 的确定性渲染完全一致

8.2 Collision / Residual MUST / DAG

只允许：
Primary Root Cause、真实 Target Constraint、Earlier Design 引入的新 incompatibility 成为模块 causal parent。

Validator 只机械检查：

- core node 有合法 parent；
- edge 有 validation obligation；
- 无结构性 orphan。

Reviewer 判断：collision 是否真实、repair 是否必要、模块是否最小、causal edge 是否科学成立。

8.3 Feasibility / Counterfactual

Feasibility 按 claim 检查 observability/estimability、optimization、compute/real-time、closed-loop/stability、safety/physics、data/hardware、verification path。

允许 explicit unresolved debt + claim restriction；fatal debt 若无法 repair/restrict 且直接破坏核心 seed，可由允许 NO-GO 的 Critical Gate 终止。

method_refinement 的 formal independent reviewer verdict 冻结为：
- METHOD_READY → accept phase，进入 final_method_novelty_gate；
- REVISE → method_refinement；
- RETHINK → method_design；
- HOLD → method_refinement；
- RCA_CONFLICT → root_cause_analysis；
- NO_GO → 通过 workflow `terminal_verdicts` 和统一 `terminate_scientific_core` 路径进入 SCIENTIFIC_NO_GO。

method_refinement 的 NO_GO 仅用于 fatal feasibility debt 直接破坏核心 seed，且 repair、claim restriction 及所有其他合理 fixed-return recovery 已被 Evidence 排除的情形；它不是普通 return target。Controller 必须校验完整 no_go payload/record 后才可终止。

Counterfactual Package 在此阶段保存“必须执行/验证的最小 causal obligations”，不能把尚未执行的实验写成已经成立的 Evidence。

13. 验收标准
======================================================================

修改完成必须同时满足：

A. 科研逻辑闭合

4. 每个 RMC 真实执行四类 Principle Search Coverage；cross-domain 必须先形成 Target Mechanism Signature，执行 MODEL_PRIOR + ACADEMIC_BRIDGE Domain Discovery，再对 active domain 完成 evidence-grounded Terminology Grounding 与 domain-specific problem–intervention search；跨域搜索不可跳过；
5. Source discovery provenance、Causal Efficacy、Genealogy、Intervention-Level Isomorphism、Early Target Novelty 均有正式 Evidence/closure；MODEL_PRIOR/PRACTITIONER_SIGNAL 不得冒充科学 Evidence；
6. Principle Competition 只在欠约束时发生；Human selection 前的 killer-test concept 能比较竞争解释，selection 后的 concrete Test Plan 才定义执行与成本；
7. Evidence 真正更新 Principle，Selected Principle 保留完整 accepted closure；
8. Final Method 形成最小 causal repair DAG，所有 adaptation 由真实 Target Constraints/Residual MUST 驱动；
9. Mechanism Delta、Natural Derivation、Feasibility、Counterfactual、Scientific Delta 均进入正式 Gate/Validation；
10. Top-Venue Gate 能真实拒绝“有效但不够顶刊级”的 Method；
11. Full Validation 不是 performance-only，并且只有 causal closure 后产生 Established Scientific Delta。

B. Harness 执行闭合
1. 每个新增科研结论都有 producer、artifact、reviewer、validator、gate/recovery、consumer；
2. 关键 hard Gate 失败不能靠 weighted score、文案或继续堆模块绕过；
3. Reviewer 与 Validator 职责不混淆；
4. upstream accepted state/hash 被 downstream 真正消费；
5. return 会正确 archive/invalidate downstream，并保持允许保留的历史；
6. SCIENTIFIC_NO_GO 只由声明 terminal_verdicts 的明确不可修复 Critical Gate 触发；正式迁移只消费 attested Reviewer NO_GO verdict，进入后无 current phase、validation entry、validation handoff 或 scientific action；
7. 不存在 live 双轨 Final Method machine authority、从 FINAL_PROPOSAL 恢复 machine truth 的 parser 或 compatibility fallback；现有 reviewer verdict/metadata 载体保持不变，仅作必要 contract 扩展；
8. 与本任务无关的现有行为保持不变。

14. 验证方式
======================================================================

14.1 Requirement-to-Harness 静态矩阵

对冻结科研标准中每条需进入 Harness 的规则，逐项证明：
Requirement → Producer/Cognition → Artifact → Reviewer → Validator → Gate/Recovery → Consumer。

Phase I 的跨案例科研标准形成过程不得误变成每次 Runtime 必执行步骤。

14.2 Validator 单元测试

至少覆盖：
- Necessity binding、coverage boundary、identity disposition；
- Necessity Test Evidence 的 TEST_SPEC_REGISTERED → 必要时 EXECUTION_APPROVED → EXECUTION_HANDED_OFF → RESULT_AVAILABLE/NO_RESULT 生命周期、event/hash/current phase/problem/version binding，以及历史记录不得自动成为 current Evidence；
- RCA necessity/residual binding；
- RMC fields 与 primary-chain disposition；
- four-space search coverage；Target Mechanism Signature、MODEL_PRIOR/ACADEMIC_BRIDGE mandatory discovery、conditional PRACTITIONER_SIGNAL、Domain Terminology Grounding、domain-specific search、iterative domain expansion 与 mandatory cross-domain execution；
- pre-search signature/domain-hypothesis/query binding、Source discovery bridge、structured genealogy、causal efficacy、intervention-level isomorphism、target-equivalence refs；
- constrained/underconstrained Candidate handling；
- Candidate killer-test concept 与 concrete Test Plan 边界、Rival Pattern A/B、performance-only test rejection；
- Evidence Update target/consequence closure、PRINCIPLE_EVALUATION_VERDICT 的七类 formal decision 映射、Main consequence 不得直接驱动 transition，以及 REVISE_EVALUATION/MORE_EVIDENCE 不得混淆；
- Selected Principle materialization；
- collision/Residual MUST/DAG acyclic/no-orphan；
- Mechanism Delta/Natural Derivation/Feasibility/counterfactual/claim obligations；
- Top-Venue hard FAIL 不可被 score 抵消；
- method_refinement/Top-Venue 的 terminal_verdicts、review request allowed-verdict union、NO_GO payload/record 与 terminal invariants；
- Full Validation exact coverage、NECESSITY_PREMISE_REJECTED 固定回退与 Established Delta subset。

14.3 Reviewer/Validator Responsibility Regression

构造“schema 完全合法但科学语义错误”的 artifact，例如：
- surface analogy；
- 虚假的 Natural Derivation；
- 有合法 parent ID 但科学上不必要的模块。

预期：Validator PASS；Reviewer FAIL；Gate BLOCK/RETURN。

14.4 Controller 集成负例

至少覆盖：
1. Simple Repair full coverage → 不进入 RCA；
   若裁决依赖目标域 empirical/analytical result，未完成 Controller-bound necessity test/result registration 时不得通过；
   未注册 TEST_SPEC_REGISTERED 不得 handoff；需要 Human approval 时缺少 EXECUTION_APPROVED 不得 handoff；未达到 RESULT_AVAILABLE/NO_RESULT 不得形成引用该 test 的 NECESSITY_CLOSURE；
2. partial coverage + same problem → RCA 绑定 residual envelope；
3. partial coverage + redefined problem → 返回完整 Problem Gate 链；
4. necessity unresolved → 补 Evidence；
5. 缺少 Target Mechanism Signature，或 MODEL_PRIOR / ACADEMIC_BRIDGE 任一 mandatory Domain Discovery 未执行 → cross-domain coverage 不得完成，Method Design 不能 ready；
6. 未先注册/bind domain hypothesis 与 evidence-grounded terminology map 就直接搜索/接受 Source，或 Source 出现后才反向补造 discovery hypothesis → block；
7. PRACTITIONER_SIGNAL 发现的 domain/term/method family 未回到正式学术 Evidence 验证 → 不得形成 Source Mechanism 或 active Candidate；
8. mandatory Domain Discovery + terminology-grounded cross-domain search 已闭合但 zero credible source → 允许继续非跨域 Principle；
9. 表面问题/算法相似但 Source Intervention 未改变 Target RMC 要求的 causal/computational variable → Reviewer FAIL，Source 不得生成 active Candidate；
10. Source mismatch → method_design；
11. RMC/RCA conflict → RCA；
12. underconstrained 但无真实 competition → block；
13. test 无辨识力 → principle_test_design；
14. interpretation/attribution 错误但原始 result 有效 → Reviewer verdict REVISE_EVALUATION，留在 principle_evaluation，不得重跑；operationalization/test validity invalid → MORE_EVIDENCE，新 test cycle + Human re-approval；Main 的 scientific_updates[].consequence 不得直接改变 phase；
15. Principle Evaluation 发现 residual/Necessity conflict → Reviewer verdict NECESSITY_CONFLICT → problem_necessity；发现 Problem identity/premise conflict → PROBLEM_CONFLICT → problem_generation；
16. fatal feasibility 可修/可限 claim → method_refinement 的 REVISE/HOLD；不可修且 Reviewer formal verdict 为 NO_GO、terminal bindings/record 完整 → SCIENTIFIC_NO_GO；
17. Target intervention covered → 淘汰/返回正确层；
18. Top-Venue 任一 critical criterion FAIL → 不得进入 Final Human Gate；
19. Full Validation performance-only/义务漏项 → 不得 VALIDATED。
20. Full Validation 推翻 Necessity premise → problem_necessity；推翻 Problem premise → problem_generation。
21. SCIENTIFIC_NO_GO → current_phase=null、无 validation entry/handoff、无 scientific action；NO_GO 被错误放入 return_targets、缺少 attested Reviewer verdict/完整 record，或仍存在合理 fixed return 时均不得进入 terminal。

15. 实施分批与停止条件
======================================================================

为降低大改风险，实施不得一次性混合完成，按依赖顺序分批：

Batch 6：Full Validation/downstream consumers/mirrors
Batch 7：当前 E2E generic migration + full regression/E2E

每个 Batch 必须先通过其 targeted tests 和 diff audit，再进入下一 Batch；若发现冻结科研标准与真实 Harness 存在新的不可执行冲突，停止实施并回到修改方案审议，不自行改变科研标准。

16. 最终完成定义
======================================================================

完成不是“Prompt/Schema 中出现了这些词”，而是：

Frozen Scientific Requirement
→ Agent 实际执行
→ Evidence/Artifact 被持久化
→ Independent Reviewer 可判断
→ Validator 可检查机械事实
→ Controller Gate 可阻断/回退/必要时 NO-GO
→ Downstream 真实消费
→ Full Causal Validation 可逐项验证。

在此基础上，现有 ARIS 的正确工程骨架、Evidence/Reviewer/Human/State/History 机制保持不变，Method Design scientific core 被最小充分地升级为能够从真实 Failure/RCA 形成并筛选 Top-Venue-Potential Strong Method Seed 的执行系统。
